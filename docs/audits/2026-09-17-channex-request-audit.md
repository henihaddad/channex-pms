# Channex request-side audit, 2026-09-17

What was checked: every operation of `packages/connectivity/src/channex/provider.ts` (39 calls in 8 areas): our request (method, path, query, body) and our response parsing against the vendored Channex pages under `docs/vendor/channex/`. Method: one agent per area produced findings; a second agent per finding tried to refute it with the code and the docs open; only findings that survived are listed as confirmed. 92 findings, 81 confirmed, 11 refuted. Severity: blocker = the call is refused or ignored; wrong_data = the call works but data is wrong or lost; info = worth knowing.

## Resolution (same day)

Live probes against Channex staging (`scripts` in the session scratchpad, results in the commit
message) settled the findings the docs left open before anything was changed:

- Rate plan titles: a second plan with the same title on the same property is refused with
  `422 "Duplication in Rate Plan title is not allowed!"` (finding 0 confirmed as a blocker).
- `days` on `POST /availability`: honoured although undocumented (finding 1 refuted; a weekend
  entry applied to Saturdays and Sundays only). The weekday encoding stays, with a note in code.
- Past dates on `/restrictions`: Channex moves `date_from` to today and answers a string warning;
  cells before the property's today are now failed locally with that reason and never sent.
- Warnings: `values=[good, bad]` answers one warning echoing the bad entry with no index
  (finding 2 confirmed); warnings are matched by the echoed keys, and the fixture is the recording.
- `test_connection` with a hotel Booking.com does not know: `200 {"data":{"success":false,"errors":null}}`.
- `GET /rate_plans` carries no `parent_rate_plan_id`; `GET /rate_plans/options` does.
- `GET /reviews?filter[updated_at][gte]=…` is accepted.

Fixed in the same commit: findings 0, 2 to 17, 19 to 21, 24 to 26, 28 to 30 and 42 (feed
pagination), each with a fixture and a contract or integration test where a request or a parse
changed. Deferred: finding 18 (a text-plus-attachments send retried as one unit) needs a per-part
delivery record on the outbound row and is tracked in spec 09.

## Refuted claims

- ? › properties.create — group_id is omitted when the local property has no group, but docs say a property must belong to a group
- ? › restrictions.push — 429 handling retries after ~1 s (or Retry-After) instead of the documented 1-minute pause; Retry-After is not documented
- ? › restrictions.push — Documented property size limits (occupancy 18, rate plans per room type) are not enforced before building `rates`
- ? › airbnb.mapping.create + channels.mapping.delete (ensureListingMappings / removeListingMappings) — No pause between mapping removal and re-creation; the async removal is read as 'still mapped' and the re-map is skipped
- ? › airbnb.mapping.create — Fixture answers 201 with attributes.rate_plan_id; docs answer 200 with attributes {id, settings} only
- ? › airbnb.listings — Documented `synchronization_category` is not read
- ? › channels.create (mapping structure) — Occupancy per mapping comes from the room type default, not from the rate's `occupancies`; OBP hotels get one occupancy per rate and `occupancy` can be omitted although Booking.com requires it
- ? › parseRevision — services[].is_inclusive does not exist in the documented Booking Service; isInclusive is always false
- ? › parseRevision — Card data is only served on the secure endpoints; our base URLs are app./staging.channex.io
- ? › reviews.guest_review — Guest review body matches the docs; `private_review` is sent as an empty string when the host wrote none, which the docs do not show
- ? › transport.classify (404) — 404 is mapped to ValidationError together with 400 and 422

## How to keep this true

- The docs are vendored under `docs/vendor/channex/` (`node scripts/channex-docs-sync.mjs`; `--check` reports staleness).
- Every Channex call cites its page in a `// docs:` comment; `pnpm check` fails otherwise (`scripts/check-channex-docs-refs.mjs`).
- A new or changed operation gets a fixture from the documented response and a contract test asserting the request body.
- Check what we send as carefully as what we parse: the mismatches that broke real connections were on the request side.
